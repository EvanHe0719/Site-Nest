# 每日签到脚本

## 用户行为

每个已适配站点的签到卡片提供：每天 HH:mm、自动执行开关、立即签到、打开页面及上次运行结果。时间为电脑本地时间，只在栖页运行时有效，不注册 Windows 后台任务，不唤醒关机电脑。

启动及唤醒后由统一轮询检查当天已到时间的任务，不补发前几天的签到。每站点每天自动尝试一次；登录失效、验证码或网络错误会保留原因，当天不反复访问，用户处理后可以立即签到。已确认当天成功时，自动和手动入口都不会再次提交。

NodeSeek 默认不开启自动执行。请先从卡片打开页面，在 NodeSeek 专用身份中登录，然后设定时间并开启。它只检查官方 `/board` 页面并点击可见的明确签到控件，不猜测或调用未确认的私有接口。页面显示个人当天签到奖励后才算成功。实站页面结构和账号环境尚未通过真实登录验收，可能显示需要人工处理。

## 添加新适配脚本

1. 在 `electron/automations/checkins.cjs` 的 `CHECKIN_DEFINITIONS` 注册稳定 ID、名称、入口、颜色和默认开关；新站点通常默认关闭。
2. 在主进程 `getCheckinScheduler()` 注册对应 runner。runner 必须限定站点、复用正确登录身份、设置超时、处理登录与验证、检查真实结果、销毁自己创建的资源。
3. 返回 `{ status, message }`，status 只能为 `success / needs-login / needs-action / error`。只有站点确认结果才能返回 success。
4. 不为新站点另外写定时器、设置 IPC 或点击事件。统一调度会保存 `automations[id]`、去重、写入最近 30 次记录，前端根据 definitions 生成相同卡片。
5. 补充站点页面回归，再进行经授权的实站验证。任意导入的网页脚本不会自动成为后台签到任务。

旧奶昔设置原样迁移。新增字段使用默认值，不提高 schemaVersion。执行记录保存在本机；云同步设置仍遵守既有字段白名单。

## 验证

- `test/unit/checkin-scheduler.test.cjs` 覆盖独立时间、关闭、跨天、失败重试、并发去重、设置校验和新增适配器复用。
- `checkin-settings-probe` 在隔离数据目录通过实际界面与 IPC 修改设置、执行本地模拟 runner、重启读取；不会访问真实签到接口。
