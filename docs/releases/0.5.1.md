# 栖页 0.5.1：SAP Support 登录跳转修复

发布日期：2026-08-30

## 已确认原因

- SAP Support 的关键词搜索目标为 `https://me.sap.com/servicessupport/search/?q=...`，随后由 SAP for Me 启动 OAuth/SAML。
- 使用 Electron 44、与栖页相同的 User-Agent 处理和临时空白分区进行线上只读探针，实际链路可以正常到达 `accounts.sap.com/saml2/idp/sso`，没有出现危险字符错误。
- 用户栖页分区的只读审计发现 `.sap.com` 父域 Cookie；旧修复只匹配 `support.sap.com`、`me.sap.com`、`accounts.sap.com` 和精确 authentication 子域，遗漏父域 Cookie，因此无法真正恢复成空白 SAP 登录环境。

## 修复内容

- 新增 `electron/browser/sap-auth-recovery.cjs`，把 SAP 页面识别、父域 Cookie 边界、返回目标和会话清理从界面逻辑中分离。
- 用户点击并确认“修复 SAP 登录”后，清理栖页持久分区内 `.sap.com`、SAP 子域与 `.hana.ondemand.com` 认证域 Cookie，以及已访问 SAP 登录 Origin 的 LocalStorage、IndexedDB、Service Worker 和 Cache。
- 非 SAP Cookie 不清理；外部 Chrome 不受影响。该操作会退出栖页内所有 SAP 站点账号，因此继续保留明确确认步骤，不自动执行破坏性清理。
- 在打开、重定向和页内导航阶段持续记住原始 SAP for Me 搜索/Note URL；清理后以原字符串重试，保留关键词及其编码。
- 页面错误状态给出明确说明，修复按钮仍只在识别到 SAP 拒绝页后显示。

## 使用方式

1. 在 SAP 报错页点击右上角“修复 SAP 登录”。
2. 阅读提示并确认；这会退出栖页内 SAP 账号，但不会影响 Chrome。
3. 栖页自动重新打开刚才的 SAP 搜索结果，并应进入 SAP for Me 登录页。
4. 登录成功后继续查看目标搜索结果或 Note。

## 尚需现场确认

自动化测试不能代替用户 SAP 账号登录。成品需要由用户在实际账号环境完成用户名、验证码或组织登录，并确认登录后的最终搜索结果；栖页不会读取或自动填写密码。
