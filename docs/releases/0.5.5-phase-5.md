# 0.5.5 开发迭代 Phase 5：网页脚本平台化

本阶段保持正式 App Version `0.5.5` 不变，只将本地数据 schema 提升到 `16`，用于保存用户脚本版本历史。

## 已实现

- 支持本地 `.user.js`、粘贴源码、HTTPS 地址、浏览 `.user.js` 时提示安装，以及在栖页内新建脚本。
- 安装和更新前展示 Metadata、匹配/排除网址、运行时机、权限、跨域范围、远程依赖、更新地址、兼容性、Hash 和代码差异。
- `UserScriptVersion` 至少保留当前与上一版本；更新必须显式确认，支持显式回滚。
- 删除采用软删除，15 秒内可在提示中撤销，之后仍可从回收站恢复；脚本存储、版本和执行记录不删除。
- 支持首阶段 GM API：样式、隔离存储、菜单命令、同身份打开页签、应用内/系统通知、剪贴板和受控跨域请求。
- 跨域请求逐次检查重定向、去除凭据头、不给第三方附带 Cookie、限制 1 MB 和 30 秒；localhost 另需高级确认。
- 脚本在独立 isolated world 中运行，Node、Electron、任意 IPC、Cookie 和密码不可见；敏感页面继续由固定策略阻止。
- 匹配、注入与首次执行耗时进入执行记录；Observer、Timer、长任务和错误次数进入运行统计。连续三次严重错误会自动暂停并产生应用内提示。
- 执行指标采用 2 秒批量持久化，避免每次脚本执行都同步重写状态文件。

## 兼容性边界

- `@require`、`@resource`、`unsafeWindow` 和通配 `@connect *` 当前不支持，并会在安装审查中明确阻止或提示。
- `document-start` 仍由现有 `PageCapabilityOrchestrator` 在页面 DOM 就绪阶段调度，因此不保证早于站点自身脚本；Metadata 审查会明确显示此限制。
- 应用目前没有独立的持久化“通知中心”数据模型；`GM_notification` 进入应用内 Toast 通道并同时尝试系统桌面通知，但应用内提示不会跨重启保留。
- 本阶段没有运行任何打包命令，也没有生成便携版、MSI、安装 EXE 或 Release。
