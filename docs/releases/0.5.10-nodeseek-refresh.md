# 栖页 0.5.10：NodeSeek 刷新修复

## 已复现的问题

在与正式应用相同的 NodeSeek 持久分区、系统代理和真实工具栏上，首次访问首页返回 200；Service Worker 接管后，两次点击刷新均返回 403，正文只有 `403`。这些失败未被旧版仅检查标题和特定正文的规则识别。

请求记录显示：首次导航使用标准 Chromium User-Agent；后台服务发起的请求却使用应用级回退值，重新带入应用标记和 Electron 标记。只设置 `session.setUserAgent()` 未覆盖这一请求路径。

在同一已经失败的隔离测试数据目录中，仅统一应用级回退 User-Agent 后，重新打开与连续两次刷新均返回 200。此次比较未清理 Cookie、Service Worker 或缓存，也未更换代理。网站后台具体采用哪条拒绝规则不可见，不推断其内部风控策略。

## 实现

- 在创建会话和网页前设置 `app.userAgentFallback`，与既有页面会话共用当前 Chromium 版本的标准标识；不伪造其他版本，不轮换身份。初始化时机符合 [Electron 全局回退标识说明](https://www.electronjs.org/docs/latest/api/app#appuseragentfallback)。
- NodeSeek 首选语言向 Electron 传入 `zh-CN,zh,en`，由 Chromium 正常生成权重，避免 `q` 参数重复，符合 [Electron 语言参数要求](https://www.electronjs.org/docs/latest/api/session#sessetuseragentuseragent-acceptlanguages)。
- 读取主框架真实 HTTP 状态码，补上空标题、纯 `403` 页面识别；只有出现相应验证标记时才显示网站安全验证提示。
- 拒绝访问提示放在工具栏下方，网页视图按实际布局下移；成功导航后移除提示。异步旧文档检查不会把过时错误写到新页面，也不会触发过期网络重试。
- 普通刷新保留原 `WebContentsView`、持久分区及站点登录数据；不新增自动清理、自动换代理或循环重试。

## 回归覆盖

- 本地真实 HTTP 服务和 Service Worker 模拟导航接管，验证首次请求及两次后台服务刷新使用相同 User-Agent、有效语言头，登录 Cookie 不变。
- 完整应用通过隔离 HTTPS 测试响应复现 `403 → 403 → 200`，验证提示可见、网页不被遮挡、恢复后清除提示，所有操作来自实际刷新按钮。
- 单元回归覆盖域名边界、普通帖子误报、验证页分类，以及旧文档检查竞态。
- 实站诊断仅在显式隔离测试模式运行，只记录必要请求标识、状态码和页面概况，不记录 Cookie、授权头或完整页面正文。
- 回归测试收尾等待页面停止加载，界面测试等待完整初始化后才核对焦点，消除提前关闭和晚到初始化引起的竞态；没有放宽应用的关闭保护。
