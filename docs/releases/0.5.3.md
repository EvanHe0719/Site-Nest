# 栖页 0.5.3

> 后续结论：本版加固了多页签清理顺序，但没有消除 SAP HANA 400。完整应用跟踪在 0.5.4 确认根因是打包后 User-Agent 中的中文产品令牌。

## 修复目标

修复多个 SAP Support / SAP for Me 页签共享 `persist:qiye-sap-support` 时，“修复 SAP 登录”无法稳定清除认证拒绝状态的问题。

## 现场结论

- SAP Support 的数字搜索会打开 `https://me.sap.com/notes/{id}`，窗口参数为 `noopener,noreferrer`。
- 在全新 Electron 身份中，直达 Note、先打开 Support 再进入 Note、以及拦截后新建 WebContents 三种路径都能到达 SAP ID 登录页。
- 用户现场的 SAP 页签均已正确路由到 `sap-support`，因此问题不是查询参数、OAuth URL 或 Profile 选择。
- 旧重置流程在 SAP WebContents 仍运行时先删除 Cookie/Storage，且其它 SAP 页签继续共享该分区；在途请求可能立刻写回失效状态。

## 实现

1. 收集当前所有 SAP 运行时页签和访问过的 SAP Origin。
2. 先关闭该 Profile 的受控弹窗、拆出窗口和全部 SAP WebContents，但保留页签记录。
3. 先终止网络连接，再清除 SAP 专用分区的全部 Cookie、站点存储、缓存和认证缓存；完成后再次终止连接并检查 Cookie 已为零。
4. 只重建当前页签并重新进入原始 Note / Search 目标；其它 SAP 页签保持休眠。
5. 非 SAP 页签继续使用 `persist:qiye-sites`，不会被清理或退出登录。

## 验证范围

- 单元测试覆盖连接终止顺序、整分区清理、受控弹窗 Profile 隔离与全部 SAP 页签暂停。
- 真实 Electron 回归同时验证 SAP 专用分区被清空、默认分区 Cookie 仍保留。
- 发布前执行 syntax、lint、typecheck、unit、integration 和 Windows 便携版构建。
