# 栖页 0.5.4

## 修复目标

修复 SAP Support 搜索或直接进入 SAP for Me 后，HANA 认证页返回 “The request was rejected because it contained a potentially malicious character.” 的问题。

## 已确认根因

- 外部 Chrome 和最小 Electron 探针都能进入 SAP ID 登录页。
- WebContentsView、预加载脚本、弹窗转页签、系统代理、权限处理器和独立 SAP 分区均已逐项 A/B 排除。
- 在完整栖页中捕获到的实际 User-Agent 含 `栖页/0.5.3`；这是 Electron 根据打包 `productName` 注入的非标准中文产品令牌。
- 同一个 OAuth 请求因此在 HANA 返回 400；成功探针的 User-Agent 是纯 ASCII 标准 Chrome 格式。

## 实现

1. 从当前 Chromium User-Agent 保留平台和 Chrome 版本。
2. 重新生成标准 `Mozilla/5.0 ... Chrome/... Safari/537.36` User-Agent。
3. 删除 Electron、英文包名和中文产品名等应用令牌。
4. 对所有内嵌站点统一应用，避免其它严格网关出现同类兼容问题。
5. 不改写 URL、OAuth 参数、Cookie、代理或浏览分区。

## 真实验证

- 使用隔离本地数据启动完整栖页并打开 `https://me.sap.com/notes/1313`。
- 修复前：`/oauth/authorize` 返回 400，并显示 malicious character 页面。
- 修复后：同一完整应用会话到达 `https://accounts.sap.com/saml2/idp/sso`，页面标题为“SAP for Me: 登录”。
- 使用 0.5.4 便携版成品重复验证，持久状态记录的目标仍为 `accounts.sap.com/saml2/idp/sso`，不是开发探针或模拟页面。
- 单元回归验证生成结果为 ASCII 且不含 `栖页`、`Electron` 或 `site-nest-desktop`。

## 数据边界

- 不清空 Chrome、NodeSeek、Zoho、奶昔或其它非 SAP 登录状态。
- 不改动用户站点、页签、书签、Google 同步或自动化数据。
